## Deviations from the brief (planning please review)
1. **Stacked base** instead of "after merged to develop" (top of this report).
2. **`LINKEDIN_ACADEMY_POST_FROM` is validated more strictly than `LINKEDIN_POST_FROM`:** it must start `YYYY-MM-DD` and parse (`Date.parse('2026')` is 1 Jan and `04/11/2026` is April; with no age limit a go-live typo would flood the page with everything pushed since). A bare date is UTC midnight; a zone-less time is read in server local time, so use a `Z` time. `LINKEDIN_POST_FROM` still uses a bare `Date.parse`, untouched.
3. **The registry is `env.linkedin.sharedPages`** (keyed by page, with `tokenFrom`), not an `env.linkedin.academy`, so tests can use private page names; and the LinkedIn `PORTAL_TO_PAGE` constant is gone (function `portalPages()` instead).
4. **`tokenShared` is omitted (not `false`) when Academy is off**, so the old answer stays unchanged apart from `pages`. It is true while any active page borrows another page's token.
5. **A stop is per page, but its resume rule is unchanged** (a token change or renewal, or an app restart). After the owner fixes a missing admin role on the Academy page in LinkedIn, Academy stays stopped until the app restarts. The alert e-mail, the screen banner and the doc say so. A Resume button or a periodic probe would be a new feature; not built.
6. **SPA additions beyond the brief's list:** a stale-answer guard (a request counter, so one page's rows can never land under the other page's name), the old page's rows/counts/banner are cleared the moment the switch is tapped, and `invalid_page` falls back quietly to the first page. Wording with Academy off is byte-identical to today.
7. **Guide:** the amber banner text "all posting is stopped" became "posting to that page is stopped" (true with two pages), plus one sentence that the banner can show on one page only.

## Worth remembering
- **Switching it on:** set `LINKEDIN_ACADEMY_POST_FROM` to the MOMENT of switch-on. With no age limit, everything pushed since that time posts to Academy at once, three a tick behind Taxscan; the same after a restore or if Academy is switched off and on again (`docs/LINKEDIN_POSTING.md` and `.env.example` say it). The first real post proves the token's member administers the Academy page; a 403 on Academy alone is the signal that it does not.
- **Suggestions, not built:** (a) treat Academy as OFF when its org URN equals the Taxscan page's (a copy-paste slip would otherwise double-post every article to the Taxscan page); (b) `docs/BACKUPS.md:137` names only `LINKEDIN_POST_FROM` for the restore step (the brief did not list that file); (c) the guide's section 8 table still says "reached the Taxscan LinkedIn page" (true, but Academy-blind; the brief limited the guide to section 12); (d) from the screen, the OTHER page's stop is invisible (`login` follows the selected page; only admins get the e-mail): a later change could return `stopped: ["academy"]` for a small mark on the switch; (e) `tokenShared` does not say WHICH pages share, and the SPA assumes `pages[0]` owns the token: a third page with its own token needs a field.
